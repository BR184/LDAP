# 角色组委派管理与开放角色供给实施计划

> 权威需求来源：`2026-08-04-delegated-role-group-management-design.md`

## 目标

在不改变既有 LDAP、登录和业务 API 响应契约的前提下，增加角色作用域、委派角色组管理、组/全局访问令牌、角色成员全量与增量供给，以及个人中心角色视图。

## 权威技术模型

- `sys_role` 是唯一角色定义表，通过 `SYSTEM/GLOBAL/GROUP` 作用域和可空角色组 ID 确定边界。
- `sys_user_role` 是唯一用户角色成员关系表；组角色不创建第二套成员关系，也不能绑定任何平台权限。
- 角色组及协作成员使用独立的 `sys_role_group`、`sys_role_group_member`，成员身份与委派权限形成双重门禁。
- 个人、角色组和全局令牌统一存放在 `sys_personal_access_token`，通过稳定主体类型和主体 ID 区分。
- 成员变更通过只追加、单调递增的事件表形成游标，所有 `sys_user_role` 写入口统一记录事件。
- 既有控制器响应 DTO 不增加字段；角色作用域、个人角色上下文和公开供给均使用新增 API。

## 实施顺序

1. 用单元测试固定委派权限成对、角色组成员双重门禁、作用域隔离和管理级角色禁配规则。
2. 增加 V50 迁移、角色组领域仓储、角色作用域字段、成员变更游标和令牌主体字段。
3. 实现角色组、协作成员、组角色、公开姓名检索和成员关系管理 API。
4. 实现管理员角色作用域治理，并阻止组角色绑定平台权限。
5. 扩展 PAT 主体，实现场景受限的组/全局令牌创建、查看、轮换、撤销和认证。
6. 实现开放角色供给全量/增量 API，组令牌只返回本组与全局角色，全局令牌返回全部角色。
7. 增加角色组管理页面、角色管理作用域列和个人中心“我的角色/角色组”。
8. 完成后端测试、前端类型检查与生产构建，并通过非浏览器 HTTP 验证；搜索确认旧 API DTO 未变化。

## 不变式

- `GROUP` 角色的权限关系必须始终为空。
- 委派管理和委派用户分配权限必须同时存在；对应菜单显示权限由授权服务同步。
- 被邀请但缺少委派权限的成员只能在个人中心读取参与关系。
- 委派者不能查看系统级角色，也不能分配权限等级 1/2 或内置管理角色。
- 角色组令牌只能访问开放供给 API，不进入用户权限计算。
- 令牌值不写入列表、日志或审计详情；重看必须经过短时密码验证凭证并记录审计。
- 原有 `RoleResponse`、`CurrentUserResponse`、LDAP 相关 DTO 和兼职部门数组契约保持不变。
