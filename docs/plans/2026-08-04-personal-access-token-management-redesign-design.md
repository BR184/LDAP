# 个人访问密钥管理重构设计

## 目标

将现有个人访问密钥功能重构为适合企业长期使用的桌面端密钥管理页面：创建时不再要求输入当前密码；权限按稳定业务分组选择并区分高、低风险；支持固定权限和自动跟随账号权限；有效密钥可重复复制；清单同时支持撤销和真正删除；修复部分部署环境中权限中文乱码的问题。

本次不做手机或移动端响应式交付，不改变现有 LDAP、登录、用户、部门及第三方接入 API 的路径和响应字段。

## 权威模型

### 密钥认证与保存

- 密钥格式继续为 `idm_pat_<tokenUid>_<secret>`，避免破坏已有调用方。
- 认证始终使用现有 SHA-256 摘要和恒定时间比较，不在认证热路径解密密钥。
- 经业务确认，新密钥在数据库保存完整密钥明文和 SHA-256 摘要，不再引入额外加密主密钥或密钥配置。
- 摘要是认证热路径的权威数据，完整值只服务于所有者重复查看和复制。
- 现有密钥只有摘要，无法恢复原值，迁移后标记为不可查看；用户只能删除后重建或执行密钥轮换。

### 权限模式

- `FIXED`：创建时由所选权限分组展开为账号当时实际拥有的 API 权限，并保存精确权限 ID。后续账号新增权限不会扩张密钥；权限被回收时立即失效。
- `FOLLOW_ACCOUNT`：不保存固定权限快照，认证时直接使用账号当前有效 API 权限。账号获得新权限时密钥自动获得，权限被回收时立即失效。
- 现有密钥全部迁移为 `FIXED`。
- PAT 仍然不能调用密码验证、密码修改、本人菜单和 PAT 生命周期接口。

### 权限分组

权限分组使用 `src/main/resources/security/personal-access-token-permission-groups.json` 作为版本化权威资源。每个分组包含稳定 ID、中文名称、风险等级、排序和权限编码列表。

- 风险等级只有 `LOW` 和 `HIGH`，页面分区展示。
- 同一启用 API 权限必须且只能属于一个分组。
- 分组接口只返回当前账号实际拥有的成员权限。
- `MENU` 权限不属于 API 密钥范围，不进入分组。
- 应用启动时校验数据库中每个启用 API 权限都被分组资源覆盖，避免新增权限静默消失。

## 生命周期

- 创建：只允许有效网页登录会话，不再要求密码验证凭证。
- 查看/复制：仅密钥所有者的网页登录会话可读取可恢复的有效密钥；响应禁止缓存并记录审计。
- 轮换：为现有记录生成新的 `tokenUid`、完整密钥和摘要，旧密钥立即失效；权限模式和有效期不变。
- 撤销：写入撤销时间并保留元数据和审计历史。
- 删除：事务内删除权限关系和密钥记录，密钥立即失效；审计日志保留。

## API

- 保持 `GET /api/v1/personal-access-tokens` 原有字段，并追加描述、权限模式、是否可查看等字段。
- 保持 `GET /api/v1/personal-access-tokens/available-permissions` 原响应，供已存在调用方继续使用。
- 新增 `GET /api/v1/personal-access-tokens/available-permission-groups`。
- `POST /api/v1/personal-access-tokens` 不再要求 `passwordVerificationToken`，新增 `description` 和 `scopeMode`。
- 新增 `GET /api/v1/personal-access-tokens/{id}/secret`，响应设置 `Cache-Control: no-store`。
- 新增 `POST /api/v1/personal-access-tokens/{id}/rotations`。
- 新增 `POST /api/v1/personal-access-tokens/{id}/revocations`。
- `DELETE /api/v1/personal-access-tokens/{id}` 改为真正删除。该语义只影响刚新增的 PAT 自服务 API；项目内全部调用点、测试和文档同步切换，不保留双轨内部入口。

## 桌面端交互

- `/access-tokens` 为 GitLab 风格的紧凑清单，展示名称、前缀、状态、权限模式、权限组、有效期、最近使用和操作。
- `/access-tokens/new` 为独立创建页，不使用弹窗。
- 表单纵向排列名称、描述、有效期、自动扩权开关和权限范围。
- 权限按低风险、高风险分区并分别支持全选；分组默认收起，可整组选择，也可展开后单独调整成员权限。
- 开启自动扩权后禁用固定分组选择，并在提交前对高风险授权进行确认。
- 有效且可恢复的密钥提供复制、查看、轮换、撤销和删除；旧密钥提供轮换和删除。
- 页面沿用当前中性绿色与灰色体系，不引入蓝紫色 AI 风格；仅验收桌面宽度。

## 中文乱码治理

- 所有 JDBC 模板显式使用 `characterEncoding=UTF-8` 和 `connectionCollation=utf8mb4_general_ci`。
- Flyway 显式设置 `UTF-8` 编码。
- 启动校验读取 JDBC 会话字符集，生产环境不是 `utf8mb4` 时直接失败。
- 使用稳定 `permission_code` 对标准权限名称和备注做确定性修复，不执行猜测式转码。
- 增加中文权限从迁移、数据库读取到 JSON DTO 的契约测试。

## 安全边界

- 明文保存和可重复查看密钥弱于 GitLab 的一次性显示模型，这是经业务确认后的显式取舍。
- 完整密钥不进入列表响应、日志、审计详情、异常或前端持久化状态。
- 查看接口按用户和来源 IP 限流，并审计操作人、密钥 ID、时间和来源 IP。
- 生产环境必须通过 HTTPS 或已有网关 TLS 终止访问；服务内部端口无需改变。
- 数据库备份包含可直接使用的访问密钥，应沿用数据库备份的既有访问控制。

## 验证

- 后端测试覆盖明文持久化、权限分组完整性、两种权限模式、动态扩权和收权、查看、轮换、撤销、删除、旧密钥迁移及中文修复。
- 契约测试确认现有登录、`/api/v1/auth/me`、用户和 LDAP 响应不变。
- 前端执行 `npm run check` 和 `npm run build`。
- 固定负载基准比较 JWT、`FIXED` PAT 和 `FOLLOW_ACCOUNT` PAT。
- 遵守浏览器验证禁令，不执行浏览器自动化、截图或移动端验收。
