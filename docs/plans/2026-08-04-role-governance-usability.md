# 角色治理与角色组可用性改进实施计划

> 权威设计：`2026-08-04-role-governance-usability-design.md`

## 权威实现模型

- 角色作用域继续由既有角色治理 API 修改，进入 `GROUP` 时提交明确的 `roleGroupId`。
- 权限套件由版本化资源和只读目录服务提供，只映射到现有权限 ID，不持久化套件选择状态。
- 角色组创建者使用既有 `creator` 字段解析，所有者使用既有 OWNER 成员关系聚合，不新增数据库字段或迁移。
- 前端查询缓存以当前用户 ID 为隔离边界，从属查询以当前角色组可见性和身份为启用条件。

## 实施顺序

1. 增加角色作用域回迁、权限套件资源校验、角色组创建者与所有者返回测试。
2. 运行定向后端测试，确认新增行为在实现前失败。
3. 实现权限套件目录、资源校验和只读 API。
4. 扩展角色组应用视图与响应，返回创建者姓名和所有者姓名。
5. 运行定向后端测试并修正到通过。
6. 实现角色列表多选作用域筛选和切换到角色组时的目标组对话框。
7. 在角色授权抽屉中接入权限套件，同时保留细粒度权限树编辑。
8. 修复角色组页面跨用户查询缓存与从属请求门禁，增加创建者、所有者和访问身份展示。
9. 运行完整后端测试、前端类型检查和生产构建。
10. 使用非浏览器 HTTP 请求验证服务行为；后端变更使用版本追踪脚本打包并更新本机服务。

## 不变式

- 细粒度权限 ID 集合是唯一授权提交模型。
- 绑定平台权限的角色不得切换为组角色。
- 角色组从属请求不能基于旧用户缓存自动发出。
- 不修改任何既有 LDAP 或用户 API 字段结构。
- 不修改数据库数据、端口与基础设施配置。
