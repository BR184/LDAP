# 菜单根节点隐藏与运维文档补全设计

## 1. 背景

当前菜单管理页与角色管理页的“绑定菜单”弹窗都会把技术性根节点 `uinit0 / UINIT0` 展示出来。该节点主要承担菜单树内部挂载作用，不适合直接暴露给管理人员。

同时，项目的生产配置说明、第三方系统回滚手册和交付清单虽然已经有基础，但“部署步骤、回滚步骤、监控告警、运维手册”仍缺少一份可直接执行的收口说明。

## 2. 目标

- 在前端菜单树中隐藏 `uinit0 / UINIT0`
  - 菜单管理页隐藏
  - 角色管理页的菜单绑定树也隐藏
- 不修改后端菜单数据本身
- 补齐部署、回滚、监控告警、运维手册相关文档

## 3. 非目标

- 不删除数据库中的根菜单
- 不修改后端菜单树接口结构
- 不改变菜单绑定的真实保存逻辑

## 4. 推荐方案

### 4.1 菜单树隐藏策略

采用“前端展示层过滤”的方式处理根节点：

- 若菜单树最外层节点命中 `menuCode=UINIT0` 或 `menuName=uinit0`
- 则前端直接提升其 `children` 作为真正展示树

这样可以：

- 保持后端菜单层级、绑定关系、祖先菜单补齐逻辑不变
- 避免在不同页面里让管理员看到技术性根节点

### 4.2 文档补全策略

补齐以下文档层能力：

- `docs/project-design.md`
  - 补充部署步骤、回滚步骤、监控与告警建议、最小运维手册要点
- 现有 runbook
  - 不强制拆成更多文件，优先在现有说明基础上形成可执行闭环

## 5. 实现范围

### 5.1 前端

- `frontend/src/views/menu/MenuTreeView.vue`
- `frontend/src/views/role/components/RoleMenuDrawer.vue`
- 如有必要，连带处理菜单树选择器的数据源构造逻辑

### 5.2 文档

- `docs/project-design.md`
- `docs/runbooks/production-environment-configuration.md`
- `docs/runbooks/third-party-ldap-rollback.md`

## 6. 验证方式

- 前端类型检查：

```powershell
npm.cmd run check
```

## 7. 结论

本方案通过最小前端过滤改动隐藏技术性根节点，同时补齐面向上线的运维文档收口，使界面更符合管理预期，也让项目的部署与运维说明更完整。
