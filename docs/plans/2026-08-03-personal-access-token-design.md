# 个人访问令牌设计

## 目标

为每个已启用账户提供独立的个人访问令牌页面。账户可以创建多份令牌，为每份令牌配置名称、有效期和当前账户权限的子集，并通过现有 API 使用令牌完成授权操作。

本功能不得改变现有 LDAP 服务、网页登录 JWT、API 路径、请求结构或响应字段，不得让令牌绕过用户准入、在职状态、角色权限和数据范围控制。

## 权威规则

- 令牌权限在创建时勾选，只能选择账户当时拥有且已启用的 `API` 权限。
- 令牌创建后不会自动获得账户新增权限。
- 请求时的有效权限为“令牌已选权限与账户当前权限的交集”。
- 账户权限回收、角色或权限禁用后，令牌立即失去对应能力。
- 账户被禁止使用、离职或删除后，名下所有令牌立即不能认证。
- 令牌继续受现有用户读取范围和密码重置范围约束。
- 令牌不能修改或验证账户密码，也不能创建、查看或撤销个人访问令牌。
- 有效期允许为无限期；无限期令牌仍可被撤销或因账户状态失效。

## 方案选择

采用数据库托管的不透明个人访问令牌，不采用长期 JWT，也不增加令牌换取短期 JWT 的双阶段协议。

令牌格式为 `idm_pat_<tokenUid>_<secret>`。`tokenUid` 只用于索引定位，`secret` 使用安全随机数生成 256 位熵。数据库只保存 SHA-256 摘要和显示前缀，明文只在创建成功响应中出现一次，验证时使用恒定时间比较。

## 授权模型

现有 Casbin 以资源路径和 HTTP 方法授权，但多个数据范围权限可能映射同一个接口。个人访问令牌必须准确区分权限编码，因此内部授权统一改为稳定的 `permissionCode`。

- Casbin 继续维护用户、角色和权限的实时关系。
- Casbin 策略对象从资源路径调整为权限编码。
- 控制器按权限编码调用统一授权服务；同一接口允许多个范围权限时使用 `hasAny`。
- 网页会话只校验账户当前权限。
- 个人访问令牌同时校验账户当前权限和令牌已选权限。
- 用户读取范围、密码重置范围等二次授权统一读取有效权限，不再直接读取账户完整权限。
- `resourcePath` 和 `action` 继续作为权限展示和 API 元数据保留，不改变对外字段。

## 数据模型

Flyway `V46` 新增 `sys_personal_access_token`：

- `id`：数据库主键。
- `token_uid`：令牌公开定位 ID，唯一索引。
- `user_id`：所属用户数据库 ID。
- `name`：用户填写的用途名称。
- `secret_hash`：完整令牌摘要。
- `hash_version`：摘要格式版本，初始为 `1`。
- `token_prefix`：列表展示前缀。
- `expires_at`：可为空，为空表示无限期。
- `revoked_at`：可为空，非空表示已撤销。
- `last_used_at`、`last_used_ip`：最近使用信息。
- 创建人、修改人和创建修改时间。

`sys_personal_access_token_permission` 保存令牌和 `sys_permission.id` 的关系。权限被删除或禁用后自然退出有效权限集合。

`sys_audit_log` 增加可空的 `credential_type` 和 `credential_id`，使已有业务审计能够区分网页会话和具体个人访问令牌。

## 认证流程

统一 Bearer 过滤器根据令牌前缀选择认证器：

1. `idm_pat_` 前缀交给个人访问令牌认证器。
2. 其他 Bearer 值继续交给现有 JWT 认证器。
3. PAT 认证器按 `tokenUid` 查库并恒定时间比较摘要。
4. 校验未撤销、未过期和账户统一准入策略。
5. 将凭证类型、凭证 ID 和令牌权限编码写入认证主体。
6. 方法授权校验账户当前权限与令牌权限的交集。

PAT 每次请求都读取权威状态，不缓存有效性，因此撤销和账号禁用立即生效。最近使用信息按配置时间窗口节流写入，避免每次请求产生数据库更新。

## API

- `GET /api/v1/personal-access-tokens`：分页查询本人令牌元数据。
- `GET /api/v1/personal-access-tokens/available-permissions`：查询本人当前可授予的 API 权限。
- `POST /api/v1/personal-access-tokens`：使用五分钟密码验证凭证创建令牌。
- `DELETE /api/v1/personal-access-tokens/{id}`：幂等撤销本人令牌。

创建响应是唯一返回完整令牌的接口。列表和错误响应不返回摘要、完整令牌或可用于判断令牌存在性的内部信息。

PAT 只能通过 `Authorization: Bearer` 请求头传递，不接受 URL 查询参数、Cookie 或请求体凭证。

## 页面

新增 `/access-tokens` 独立路由，放在左侧个人中心下方，所有网页登录账户可见，不依赖管理员菜单权限。

页面包含令牌分页列表、状态、前缀、权限摘要、创建时间、过期时间、最后使用时间和撤销操作。创建对话框包含名称、有效期和权限选择，支持 30、90、180、365 天、自定义日期和永不过期。创建成功后显示一次性密钥确认界面，提供复制按钮并明确关闭后不可再次查看。

## 安全与审计

- 创建令牌必须复用现有旧密码二次验证凭证。
- 令牌管理和密码接口只接受网页登录 JWT。
- 认证失败统一返回现有 `401` 包络，不区分不存在、过期、撤销或摘要错误。
- 授权失败继续返回现有 `403` 包络。
- 创建、撤销、失败认证需要审计；既有业务审计补充凭证类型和令牌 ID。
- 请求日志、SQL 日志和异常信息不得包含完整 Authorization 值或令牌摘要。
- 每账户有效令牌数量由外置配置控制，初始默认值为 20。
- 限流同时考虑令牌和来源 IP，策略参数外置并在固定负载基准后确定。

## 兼容性

- 不修改现有 API 路径、请求字段、响应字段和错误包络。
- 现有 JWT 格式和登录响应保持不变。
- LDAP DN、属性、端口、同步逻辑和第三方 LDAP 工具完全不变。
- 新认证能力仅扩展 `Authorization: Bearer` 可接受的凭证类型。
- V46 只增加令牌相关表和审计可空字段，不改写现有业务数据。

## 验证

- 单元测试覆盖生成、摘要、过期、撤销、权限子集和动态权限收缩。
- 安全测试覆盖 JWT/PAT 分流、禁用账号、令牌管理隔离、401/403 和日志脱敏。
- 授权矩阵覆盖全部权限、本人及递归下级、直属/递归/全局密码重置。
- 控制器契约测试确认旧 API 响应完全不变。
- 前端执行类型检查和生产构建。
- 不执行浏览器自动化、截图或浏览器验证。
- 建立固定并发请求基准，记录 JWT 与 PAT 的 P50/P95、数据库查询次数和最近使用写入频率。
