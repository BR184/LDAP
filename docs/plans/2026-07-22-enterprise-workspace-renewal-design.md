# 统一身份平台登录后工作区焕新设计

## 1. 状态与目标

- 状态：已确认方向，作为本轮改造的权威设计。
- 目标：将登录后的统一身份平台重构为兼具 CrownCAD 品牌辨识度、企业级数据效率、清晰权限边界和长期可维护性的工作区。
- 范围：管理布局、管理员首页、个人中心、用户/部门/角色/菜单/LDAP/邮件/导入/同步页面、表格、筛选、树形工作区、表单、抽屉、对话框、空态、加载态和响应式行为。
- 非目标：不改造登录页主体流程，不引入无真实数据来源的图表，不实现尚未出现的主题市场、插件式布局或多套皮肤并存。

## 2. 权威模型与演进原则

### 2.1 唯一实现

- 直接重写现有 `variables.scss`、`index.scss`、`AdminLayout.vue` 与 `PageContainer.vue`，不新增 `theme_v2`、`new_layout` 或兼容包装层。
- 现有页面全部同步迁移到新语义；被替代的颜色变量、CSS 类、布局分支和首页快捷入口在迁移完成后删除。
- 内部组件契约允许破坏性调整；所有调用点、测试和文档在同一批次更新。
- 仅保留已经对外形成契约的 REST API 行为。新增首页接口为平台内部 API，不提供旧接口别名或双轨响应。

### 2.2 组合与显式依赖

- Vue 页面通过 props、slots、composables 和显式 API 模块组合，不使用深层组件继承或全局可变事件总线。
- 后端首页聚合采用 `interfaces -> application -> domain repository` 的显式依赖，不从 Controller 直接访问 Mapper，不引入可变单例缓存。
- 公共组件只在至少三个页面存在相同职责时提取；单页专属布局保留在页面内部，避免提前抽象。

### 2.3 数据、配置与策略分离

- 颜色、阴影、圆角、间距、层级与动效时长集中在 `--ui-*` 设计变量中，页面不得散落新的品牌色魔法值；迁移完成后删除全部旧 `--idm-*` 变量。
- 导航改为带模式版本、稳定 ID、访问受众和边界校验的单一资源树，由它派生平铺索引与侧栏分组，不以显示文本判断权限或页面类型。
- 首页数据由稳定字段、稳定状态码和显式 DTO 定义，显示文案与数值逻辑分离；查询窗口与最近任务上限由带边界校验的配置提供。
- 所有列表上限、最近记录数量、状态映射和危险操作策略使用具名常量并校验边界，不在模板中硬编码。

## 3. 权限与信息架构

### 3.1 普通员工

- 登录后默认进入 `/profile`。
- 不显示首页菜单，也不能访问管理员首页接口。
- 只显示个人中心和后续明确授权的非敏感功能。
- 个人中心仅展示当前用户自己的身份、部门、邮箱和安全操作。

### 3.2 管理员与超级管理员

- 登录后默认进入 `/dashboard`。
- 首页仅展示聚合管理数据，不展示不必要的个人身份明细。
- 快捷操作按当前权限渲染；无权限的动作不显示，后端仍执行授权校验。
- 最近同步任务只展示任务类型、状态、时间、批次号和可执行动作，不在首页泄露导入文件内容或用户明细。

## 4. 视觉系统

### 4.1 色彩

- 基底：珍珠白、雾灰、纯白和石墨黑，形成安静、清晰的企业工作环境。
- 品牌蓝：仅用于主操作、选中状态、链接和关键数据，不作为大面积渐变背景。
- 皇冠黄：用于提醒、进度、风险和关键强调，不与品牌蓝混合生成蓝紫渐变。
- 状态色：成功、警告、危险和信息色保持足够对比度，并同时辅以图标或文字，避免只依赖颜色表达。
- 删除现有紫色强调变量和侧栏蓝紫渐变。

### 4.2 表面与层级

- 毛玻璃仅用于顶栏、侧栏边界、首页概览和短暂浮层。
- 高密度表格、表单、抽屉和对话框使用稳定实底，确保扫描与输入效率。
- 卡片圆角以 8px 为上限，减少卡片套卡片；页面优先使用连续工作区、分隔线和留白表达层级。
- `backdrop-filter` 不可用时由相同对比度的半透明/实色背景自然降级，不新增运行时分支。

### 4.3 字体与密度

- 中文字体栈：`HarmonyOS Sans SC`, `MiSans`, `PingFang SC`, `Microsoft YaHei`, sans-serif。
- 数据数字启用 tabular numerals，保证表格列和指标数值对齐。
- 页面标题保持清晰但不过度放大；正文、辅助信息、表格和按钮建立固定密度层级。
- 表格默认采用适合企业后台的紧凑密度，重要名称列保留足够宽度，操作列固定。

### 4.4 动效

- 使用具名动效变量和非线性缓动，不在页面散落独立 `transition` 参数。
- 页面首次进入采用轻量错位显现；指标变化采用短促数值/状态过渡；侧栏、抽屉和对话框采用一致的曲线。
- 动效时长控制在操作反馈范围内，不使用持续漂浮、循环发光或阻碍点击的装饰动画。
- 支持 `prefers-reduced-motion: reduce`，关闭非必要位移和错位入场。

## 5. 应用框架

### 5.1 侧栏

- 展开状态显示 CrownCAD Logo，折叠状态显示 CrownCAD Icon。
- 菜单可见性由后端授权菜单树决定；初始迁移只把首页绑定给 `ADMIN` 和 `SUPER_ADMIN`，普通员工不显示首页。
- 选中态使用品牌蓝细边、浅色表面和清晰文字，不使用蓝紫渐变。
- 收展动画保持布局稳定；窄屏切换为覆盖式侧栏并提供遮罩和 Esc 关闭。

### 5.2 顶栏

- 保留折叠按钮、面包屑、当前用户和退出操作。
- 采用轻玻璃表面与细分隔线，滚动时保持可读性。
- 不重复放置个人中心按钮，不加入无业务价值的搜索框或通知铃铛。

### 5.3 页面容器

- `PageContainer` 继续作为唯一页面骨架，但直接更新其契约与视觉，不创建替代组件。
- 支持标题、说明、状态元信息、主操作和正文工作区。
- 页面级操作始终放在标题区域或数据工具条，避免散落在空白区域。

## 6. 管理员首页

### 6.1 数据接口

- 新增内部接口：`GET /api/v1/dashboard/overview`。
- 授权：稳定权限码 `DASHBOARD_OVERVIEW_READ`，初始只绑定 `ADMIN` 和 `SUPER_ADMIN`；前端隐藏不是安全边界。
- 响应只包含聚合值、健康状态和有限最近任务，不返回用户列表或敏感快照。
- 后端使用专用 `DashboardOverviewQuery` 只读端口执行固定聚合与限制查询，不污染用户、部门、角色等领域仓储，也不由前端拉取全量列表后计数。

建议响应模型：

```json
{
  "generatedAt": "2026-07-22T15:30:00",
  "accounts": { "totalCount": 0, "enabledCount": 0, "disabledCount": 0 },
  "departments": { "totalCount": 0, "enabledCount": 0, "disabledCount": 0 },
  "roles": { "totalCount": 0, "enabledCount": 0, "disabledCount": 0 },
  "synchronization": {
    "health": "NO_DATA",
    "attentionWindowHours": 24,
    "pendingCount": 0,
    "runningCount": 0,
    "failedCount": 0,
    "partialSuccessCount": 0,
    "lastSuccessfulAt": null
  },
  "recentSyncJobs": []
}
```

- `health` 只允许 `NO_DATA`、`UNKNOWN`、`HEALTHY`、`PENDING`、`RUNNING`、`RECENT_ANOMALY`。
- 最近任务不返回 `requestJson`、`resultJson`、`errorMessage`、用户明细或组织明细。
- 后端不返回中文卡片标题、颜色或跳转地址；前端根据稳定字段与状态码展示。

### 6.2 页面内容

- 顶部状态区：欢迎信息、系统健康结论、数据更新时间和手动刷新。
- 非对称指标区：启用账号、部门、启用角色、同步异常；每项可进入对应页面。
- 同步健康区：最近任务、运行中/失败状态、批次号与重试入口。
- 待处理区：仅呈现真实失败任务或需要管理员处理的状态；无事项时给出明确正常状态。
- 常用操作区：按权限展示新增用户、文件导入、同步检查等真实入口。
- 不绘制没有时间序列来源的趋势图，不展示伪造百分比或装饰性曲线。

### 6.3 规模边界

- 聚合请求固定使用资源计数、同步摘要、最近任务三条 SQL，不加载完整实体集合。
- `app.dashboard.sync-attention-window-hours` 校验为 1–168 小时；`recent-sync-job-limit` 校验为 1–20，默认值仅存在于配置定义中。
- 使用显式 `Clock` 计算时间窗口，业务代码不散落 `LocalDateTime.now()`。
- 建立固定负载基准：MySQL 8、100 万用户、5 万部门、1 万角色、1000 万同步任务；记录 SQL 数量、响应体大小、p50/p95/p99 延迟、错误率与执行计划。
- 性能预算：固定三条 SQL、响应不超过 16KB、错误率为 0、p95 不高于 300ms、p99 不高于 600ms；预算写入基准文档而非业务代码。
- 首次实现不增加缓存；只有基准证明数据库聚合成为瓶颈后，才在应用服务边界内设计可失效缓存。

## 7. 页面模式

### 7.0 分页与规模边界

- 用户、角色和同步任务列表直接改为服务端分页，现有前端全量获取后 `slice` 的实现全部删除。
- 当前仓库只发现内部前端调用这些列表接口；实施前记录一次对外契约审计。若发现真实外部消费者，必须暂停并确认兼容对象、期限和移除条件；否则直接迁移权威响应，不保留双轨结构。
- 新增不可变的统一分页值对象与接口响应，显式校验页码、页大小和排序边界；不保留旧数组响应别名或双轨接口。
- 筛选、分页和排序由一次请求的显式参数表达；数据库使用分页查询与总数查询，不加载完整实体集合。
- 导入审核页的本地分页仅作用于当前已返回的有限审核批次，不与全局业务列表分页混用。

### 7.1 列表工作区

- 用户、角色、同步任务统一为：页面标题 -> 筛选工具条 -> 数据面板 -> 分页/批量操作。
- 筛选条件可清空、可回显；查询、重置和批量操作的层级稳定。
- 表格支持横向滚动、固定关键列、骨架加载、错误重试和明确空态。

### 7.2 树形工作区

- 部门与菜单统一为非对称双栏：左侧树导航、右侧详情与操作区。
- 宽屏固定合理树宽，窄屏切换为可开合树面板；不把两个区域压缩到不可用宽度。
- 节点选中、加载、禁用和无数据状态使用统一视觉语义。

### 7.3 配置与任务页面

- LDAP、邮件配置和文件导入按“当前状态 -> 配置/输入 -> 校验 -> 执行结果”组织。
- 高风险执行入口展示影响范围和确认信息；错误结果保留可复制的业务信息，不暴露敏感配置。
- 同步与导入状态使用一致的状态标签、时间线和详情层级。

### 7.4 抽屉与对话框

- 统一标题、说明、内容滚动区、校验反馈和固定底部操作区。
- 危险操作使用明确对象名称与影响说明；取消和确认按钮顺序一致。
- 不通过新增包装组件保留旧抽屉；直接更新现有组件和全部调用者。

## 8. 公共组件边界

- 保留并重写：`PageContainer`。
- 仅在至少三个真实调用方存在相同职责时新增：`WorkspacePanel`、`DataToolbar`、`StatusBadge`。
- 部门和菜单只有两个树形调用方，分别保留页内双栏实现；不提前抽象 `SplitWorkspace`。
- 导航桌面端与移动端共享同一个 `SidebarNavigation` DOM 与数据源，避免两套菜单分叉。
- 状态展示通过带稳定领域码的版本化映射资源统一管理；未知状态安全显示原始码，不由各页面重复编写颜色函数。
- 首页指标、首页任务列表等单页结构保留在 `DashboardView`，不提前抽象成通用框架。
- Drawer/Dialog 的一致性优先通过全局 Element Plus 变量和共享 CSS 规则实现，只有出现重复逻辑时再提取组合组件。

## 9. 数据流与错误处理

- 页面通过既有 API 模块发起请求，查询状态由 Vue Query 或页面已有状态机制显式管理。
- 首页聚合请求单向流动：路由授权 -> API 模块 -> Controller -> Application Service -> Repository 聚合 -> DTO。
- 加载态使用骨架或局部占位，不清空仍然有效的旧数据。
- 网络失败显示上下文错误与重试；401 清理会话；403 显示权限边界；业务失败保留服务端可操作信息。
- 并行数据请求互不共享可变状态；页面销毁后不回写失效视图。

## 10. 响应式与无障碍

- 删除全局 `body { min-width: 1280px; }`，改为布局级响应策略。
- 桌面端保持高密度；平板折叠侧栏；窄屏将标题操作和筛选区顺序化。
- 长表格保留水平滚动和固定操作列，不通过整体缩放牺牲可读性。
- 保证键盘焦点、Esc 关闭、可访问名称、颜色对比、错误提示与状态文本。
- Logo、图标和装饰图像使用正确 `alt` 或 `aria-hidden`。

## 11. 测试与验收

### 11.1 自动化

- 后端：Dashboard Controller 权限测试、Application Service 聚合测试、Repository 聚合查询测试。
- 前端：路由角色测试、首页数据状态测试、公共组件交互测试、关键页面渲染测试。
- 构建：`npm run check`、`npm run build`、后端单元/控制器测试和主工程测试。
- 搜索确认：旧颜色变量、旧首页快捷入口、被替代 CSS 类和废弃符号均无引用。

### 11.2 浏览器验收

- 管理员、普通员工两类账号分别验证默认入口、菜单和直接 URL 访问。
- 覆盖 1440、1280、1024、768 和窄屏视口；验证侧栏、表格、树、抽屉和对话框。
- 验证正常、加载、空数据、接口失败、无权限、会话失效和减少动态效果模式。
- 对关键页面保存基准截图，检查溢出、截断、对比度和动画阻塞。

## 12. 删除与迁移规则

- 新设计落地时直接更新所有页面，不保留旧主题开关。
- 删除旧紫色变量、旧侧栏渐变、旧首页快捷入口和重复工具条样式。
- 删除用户、角色和同步任务的浏览器端全量分页逻辑与旧数组响应模型。
- 若公共组件替代页面内重复结构，所有调用点同批迁移后删除旧结构。
- 删除未接入路由且只含假数据的 `PermissionTreeView.vue`，并在确认零引用后删除 Vite 示例与已被 CrownCAD 资源替代的旧图片。
- 每个阶段结束使用 `rg` 搜索被替代符号；存在引用则该阶段不算完成。
- 不为旧快照或旧内部组件测试保留错误 DOM；测试同步更新到新权威行为。

## 13. 完成标准

- 管理员首页展示真实、受权限保护且可操作的聚合数据。
- 普通员工没有首页菜单、路由访问或敏感接口访问能力。
- 所有登录后页面使用同一视觉系统并覆盖完整交互状态。
- 不存在蓝紫 AI 风格、装饰性虚假数据、旧新主题双轨或 `v2` 命名。
- 关键规模路径有固定负载基准记录，前后端构建与测试通过。
- 设计文档、API 文档和项目设计文档同步更新。
